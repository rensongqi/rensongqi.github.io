0.2 三种部署工具怎么选

工具官方态度特点推荐场景
cephadm官方主推容器化部署（podman/docker），自带编排、升级、OSD 自动发现；但对网络/镜像源有要求，排障需要懂容器新集群首选（如果你能接受容器化）
ceph-ansible社区维护传统裸机部署，Playbook 清晰可读，变量丰富；仍是大量存量集群的事实标准本手册重点。已有 Ansible 体系、要求裸机部署、需要完全掌控
手动部署官方不推荐日常使用一步步敲命令，每一步都看得见学习原理、排障、小规模/特殊环境。本手册第二部分
本手册的组织方式：第二部分用手动部署让你看清"每一步到底做了什么"（这也是 Ansible 在背后做的事）；第三部分用 ceph-ansible 把它工程化。附录 A 给出 cephadm 的极简方案。
建议顺序：先按第二部分完整手动跑一遍（哪怕是虚拟机），再用 Ansible 部署生产环境。

1部署前规划

1.1 硬件最低要求

角色CPU内存磁盘网络
MON4 核8 GB50 GB（OS）+ SSD 存 mon 数据10 GbE
MGR4 核8 GB与 MON 共用10 GbE
OSD（HDD）1 核 / OSD4 GB / OSD + 8 GB 系统1 盘 1 OSD + 独立 db/wal SSD25 GbE
OSD（NVMe）2~4 核 / OSD6~8 GB / OSD高 DWPD 企业级 NVMe100 GbE
MDS4~8 核16~32 GB元数据池建议 SSD/NVMe10 GbE
RGW4~8 核8~16 GB—10~25 GbE

1.2 网络规划要点

  • 双网分离：public_network（业务）+ cluster_network（复制），物理或 VLAN 隔离。生产必做。
  • 万兆起步：HDD 集群最低 10G，全闪必须 25G/100G。
  • MTU 9000（巨帧）：交换机、网卡两端都要配，并逐台验证 ping -M do -s 8972。
  • 禁止 NIC bonding 的 balance-rr：推荐 active-backup 或 802.3ad(LACP)。
  • 防火墙：开放端口见附录 19.1（MON 3300/6789、OSD 6800-7300、MGR 9283、RGW 7480、Dashboard 8443）。

1.3 关键规划决策清单

副本数 size = ?

生产推荐 3（容忍同时坏 2 个 OSD）；测试用 2。osd_pool_default_size = 3，min_size = 2。

MON 数量 = ?

奇数：3 或 5。跨机柜的大集群用 5。绝不用 4。

故障域 = ?

默认 host。大集群（≥3 机柜）建议 rack。绝不用 osd。

PG 数 = ?

按 200 PG/OSD 预算：(OSD数 × 200) / size，取 2 的幂。或直接开 pg_autoscaler。

db/wal 是否分离？

HDD 集群：必须分离到 SSD/NVMe（性能提升最明显）。全闪：可不分离或只分 wal。

是否用 EC？

RBD/CephFS/热数据 → 副本；RGW 冷数据/备份 → EC 4+2 或 8+3。

MON 之间时钟偏差超过 0.05s 会导致集群告警甚至无法工作。务必配置 chrony。

# 编辑 /etc/chrony.conf，指向内网 NTP 服务器
server 10.10.10.1 iburst
# 验证

# Ubuntu: apt install -y chrony

2.3 关闭 SELinux / 防火墙（或放行端口）

# 方式一：测试/内网环境直接关闭（简单）
setenforce 0
sed -i 's/^SELINUX=enforcing/SELINUX=permissive/' /etc/selinux/config
systemctl disable --now firewalld

# 方式二：生产环境放行端口（推荐）

firewall-cmd --permanent --add-port=9283/tcp    # Prometheus
firewall-cmd --permanent --add-port=7480/tcp    # RGW
firewall-cmd --reload
# Ubuntu: ufw allow 3300/tcp ... 或 ufw disable

2.4 创建 ceph 用户与免密 sudo

useradd -d /home/ceph -m ceph
echo "ceph:YourPassword" | chpasswd

# 从部署机（或第一个 MON 节点）配置到所有节点的 SSH 免密

3.2 磁盘清理与检查

# 1. 查看磁盘，确认设备名（务必确认！选错盘会丢数据）
lsblk -o NAME,SIZE,TYPE,MODEL,SERIAL,WWN
lsscsi

# 2. 检查是否有残留（重要：有 GPT/LVM/RAID 签名会导致 ceph-volume 拒绝）
wipefs -a /dev/sdb   # 谨慎！只在确认是数据盘时执行
sgdisk --zap-all /dev/sdb
dd if=/dev/zero of=/dev/sdb bs=1M count=100 oflag=direct,dsync

# 3. 确认磁盘未被占用
lsblk -f /dev/sdb
# 正常应无 FSTYPE、无 MOUNTPOINT

# 4. 检查磁盘健康
smartctl -a /dev/sdb | grep -Ei 'reallocated|pending|uncorrectable|wear'
# HDD 看 Reallocated_Sector_Ct、Current_Pending_Sector
# SSD/NVMe 看 Percentage Used、Media_Wearout_Indicator

# 5. 关闭磁盘写缓存（HDD，防止掉电丢数据）
hdparm -W 0 /dev/sdb

# 6. 设置 IO 调度器
echo mq-deadline > /sys/block/sdb/queue/scheduler   # HDD
echo none        > /sys/block/nvme0n1/queue/scheduler  # NVMe
生产环境务必用 /dev/disk/by-id/ 而不是 /dev/sdX！内核重启后 sdb/sdc 的顺序可能变化，导致 OSD 挂载错误的盘。用 wwn- 或 scsi- 开头的 by-id 链接：
ls -l /dev/disk/by-id/ | grep -v part
# 例如使用：/dev/disk/by-id/scsi-35000c500a1b2c3d4

4.2 部署流程总览

5【手动部署】部署 MON

5.1 生成 fsid 与 ceph.conf

# 在 ceph-mon1 上执行
UUID=$(uuidgen)
echo $UUID
a7f3c2e8-4b1d-4f9a-9c3e-8d2b5a1f6e70

cat > /etc/ceph/ceph.conf <<EOF
[global]
fsid                      = a7f3c2e8-4b1d-4f9a-9c3e-8d2b5a1f6e70
mon initial members       = ceph-mon1, ceph-mon2, ceph-mon3
mon host                  = 10.10.10.11, 10.10.10.12, 10.10.10.13
public network            = 10.10.10.0/24
cluster network           = 192.168.100.0/24

auth cluster required     = cephx
auth service required     = cephx
auth client required      = cephx

osd pool default size     = 3
osd pool default min size = 2
osd pool default pg num   = 128
osd pool default pgp num  = 128

mon allow pool delete     = true

[mon]
mon clock drift allowed   = 0.5
mon osd down out interval = 600

[osd]
osd recovery max active   = 3
osd max backfills         = 1
EOF
配置项说明：
· mon initial members / mon host：必须写全，这是 bootstrap 时生成 monmap 的依据
· public network / cluster network：双网分离的核心配置
· osd pool default min size = 2：3 副本下，只剩 1 副本时停止写入（防止脑裂），生产务必设为 2
· mon allow pool delete = true：允许删池（默认禁止，安全起见；测试环境可开）

5.2 生成 keyring（密钥环）

# ① MON 自身的 keyring（mon. 对 MON 有全部权限）
ceph-authtool --create-keyring /tmp/ceph.mon.keyring --gen-key -n mon. --cap mon 'allow *'

# ② client.admin（管理员，最高权限）
ceph-authtool --create-keyring /etc/ceph/ceph.client.admin.keyring \
  --gen-key -n client.admin \
  --cap mon 'allow *' --cap osd 'allow *' --cap mds 'allow *' --cap mgr 'allow *'

# ③ bootstrap-osd（用于后续添加 OSD 时向 MON 注册）
mkdir -p /var/lib/ceph/bootstrap-osd
ceph-authtool --create-keyring /var/lib/ceph/bootstrap-osd/ceph.keyring \
  --gen-key -n client.bootstrap-osd \
  --cap mon 'profile bootstrap-osd' --cap mgr 'allow r'

# ④ bootstrap-mds / bootstrap-rgw / bootstrap-mgr（可选，后面会用到）
mkdir -p /var/lib/ceph/bootstrap-{mds,rgw,mgr}
ceph-authtool --create-keyring /var/lib/ceph/bootstrap-mds/ceph.keyring \
  --gen-key -n client.bootstrap-mds --cap mon 'profile bootstrap-mds'
ceph-authtool --create-keyring /var/lib/ceph/bootstrap-rgw/ceph.keyring \
  --gen-key -n client.bootstrap-rgw --cap mon 'profile bootstrap-rgw'
ceph-authtool --create-keyring /var/lib/ceph/bootstrap-mgr/ceph.keyring \
  --gen-key -n client.bootstrap-mgr --cap mon 'profile bootstrap-mgr'

# ⑤ 把所有 key 合并进 mon keyring（MON 需要持有它们才能分发）
ceph-authtool /tmp/ceph.mon.keyring --import-keyring /etc/ceph/ceph.client.admin.keyring
ceph-authtool /tmp/ceph.mon.keyring --import-keyring /var/lib/ceph/bootstrap-osd/ceph.keyring
ceph-authtool /tmp/ceph.mon.keyring --import-keyring /var/lib/ceph/bootstrap-mds/ceph.keyring
ceph-authtool /tmp/ceph.mon.keyring --import-keyring /var/lib/ceph/bootstrap-rgw/ceph.keyring
ceph-authtool /tmp/ceph.mon.keyring --import-keyring /var/lib/ceph/bootstrap-mgr/ceph.keyring

chown ceph:ceph /tmp/ceph.mon.keyring
chown -R ceph:ceph /var/lib/ceph/bootstrap-*

5.3 创建 monmap 并初始化第一个 MON

# ① 创建 monitor map
monmaptool --create \
  --add ceph-mon1 10.10.10.11 \
  --add ceph-mon2 10.10.10.12 \
  --add ceph-mon3 10.10.10.13 \
  --fsid a7f3c2e8-4b1d-4f9a-9c3e-8d2b5a1f6e70 \
  --clobber /tmp/monmap

monmaptool --print /tmp/monmap   # 验证

# ② 初始化 mon 数据目录（目录名必须是 ceph-<主机名>）
mkdir -p /var/lib/ceph/mon/ceph-ceph-mon1
chown -R ceph:ceph /var/lib/ceph/mon

sudo -u ceph ceph-mon --cluster ceph --mkfs \
  -i ceph-mon1 \
  --monmap /tmp/monmap \
  --keyring /tmp/ceph.mon.keyring

# ③ 建立 systemctl 启动标记
touch /var/lib/ceph/mon/ceph-ceph-mon1/{done,systemd}
chown ceph:ceph /var/lib/ceph/mon/ceph-ceph-mon1/{done,systemd}

# ④ 启动
systemctl enable --now ceph-mon@ceph-mon1
systemctl status ceph-mon@ceph-mon1

# ⑤ 验证（此时 quorum 只有 1 个，会出现告警，正常）
ceph -s

5.4 扩展 MON 到 3 节点

# ① 把配置文件和 keyring 复制到其他 MON 节点
for h in ceph-mon2 ceph-mon3; do
    scp /etc/ceph/ceph.conf              root@$h:/etc/ceph/ceph.conf
    scp /etc/ceph/ceph.client.admin.keyring root@$h:/etc/ceph/ceph.client.admin.keyring
    scp /tmp/monmap                      root@$h:/tmp/monmap
    scp /tmp/ceph.mon.keyring            root@$h:/tmp/ceph.mon.keyring
done

# ② 在 ceph-mon2 上执行（ceph-mon3 同理，改 -i 参数）
mkdir -p /var/lib/ceph/mon/ceph-ceph-mon2
chown -R ceph:ceph /var/lib/ceph/mon
chown ceph:ceph /tmp/ceph.mon.keyring

sudo -u ceph ceph-mon --cluster ceph --mkfs -i ceph-mon2 --monmap /tmp/monmap --keyring /tmp/ceph.mon.keyring
touch /var/lib/ceph/mon/ceph-ceph-mon2/{done,systemd}
chown ceph:ceph /var/lib/ceph/mon/ceph-ceph-mon2/{done,systemd}
systemctl enable --now ceph-mon@ceph-mon2

# ③ 回到 ceph-mon1 验证
ceph -s
  mon: 3 daemons, quorum ceph-mon1,ceph-mon2,ceph-mon3 (age 30s)

ceph mon stat
ceph quorum_status --format json-pretty | grep -A5 quorum_names

# ④ 启用 msgr2（v2 协议，端口 3300，支持加密；Octopus+ 默认已开）
ceph mon enable-msgr2
ceph mon dump | grep -i 'addr'
常见问题：MON 起不来
· 目录名写成 /var/lib/ceph/mon/ceph-mon1 而主机名是 ceph-mon1 → 应为 ceph-ceph-mon1（ceph- + 主机名）
· 权限不对 → 必须是 ceph:ceph
· SELinux 拦截 → 临时 setenforce 0 验证
· 时间不同步 → 检查 chrony
· 看日志：journalctl -u ceph-mon@ceph-mon1 -f 或 /var/log/ceph/ceph-mon.ceph-mon1.log

6【手动部署】部署 MGR

# 在每台 MON 节点上部署 MGR（推荐：MGR 与 MON 同机部署，1 主 2 备）
# 以 ceph-mon1 为例

# ① 创建数据目录
mkdir -p /var/lib/ceph/mgr/ceph-ceph-mon1

# ② 创建 keyring（注意 daemon 名必须是 mgr.<主机名>）
ceph auth get-or-create mgr.ceph-mon1 \
  mon 'allow profile mgr' osd 'allow *' mds 'allow *' \
  -o /var/lib/ceph/mgr/ceph-ceph-mon1/keyring

7【手动部署】部署 OSD

7.1 方式一：ceph-volume lvm create（最常用，推荐）

# 前置：把 ceph.conf 和 bootstrap keyring 分发到每个 OSD 节点
for h in ceph-osd1 ceph-osd2 ceph-osd3 ceph-osd4; do
    scp /etc/ceph/ceph.conf root@$h:/etc/ceph/ceph.conf
    ssh root@$h "mkdir -p /var/lib/ceph/bootstrap-osd"
    scp /var/lib/ceph/bootstrap-osd/ceph.keyring root@$h:/var/lib/ceph/bootstrap-osd/ceph.keyring
    ssh root@$h "chown -R ceph:ceph /var/lib/ceph/bootstrap-osd"
done

# ===== 在 ceph-osd1 上执行 =====

# ① 单盘 collocated（数据与 db 在同一块盘，最简单，SSD 集群可用）
ceph-volume lvm create --data /dev/sdb

# ② 推荐的 HDD 方案：数据盘 + 独立 db（先准备 NVMe 上的 LV）
vgcreate ceph-nvme0 /dev/nvme0n1
lvcreate -L 60G -n db-osd-0 ceph-nvme0
ceph-volume lvm create --data /dev/sdb --block.db ceph-nvme0/db-osd-0

# ③ 最完整：data + db + wal 三者分离（全闪高端场景）
lvcreate -L 60G  -n db-osd-1  ceph-nvme0
lvcreate -L 4G   -n wal-osd-1 ceph-nvme0
ceph-volume lvm create --data /dev/sdc --block.db ceph-nvme0/db-osd-1 --block.wal ceph-nvme0/wal-osd-1

# ④ 批量创建（推荐，一次搞定一整台机器）
ceph-volume lvm batch --no-auto /dev/sdb /dev/sdc /dev/sdd /dev/sde /dev/sdf /dev/sdg
# 带 db 的批量：
ceph-volume lvm batch --no-auto \
  --db-devices /dev/nvme0n1 /dev/nvme1n1 \
  --db-slots 3 \
  /dev/sdb /dev/sdc /dev/sdd /dev/sde /dev/sdf /dev/sdg

# ⑤ 查看结果
ceph-volume lvm list
ceph osd tree

7.2 方式二：先 prepare 再 activate（可控性更强）

# prepare：只做 LVM 划分 + 写入 OSD 元数据，不启动
ceph-volume lvm prepare --data /dev/sdb --block.db ceph-nvme0/db-osd-0

# 查看待激活的 OSD
ceph-volume lvm list

# activate：启动（--all 激活所有）
ceph-volume lvm activate --all
# 或指定 osd id + fsid
ceph-volume lvm activate 0 a7f3c2e8-4b1d-4f9a-9c3e-8d2b5a1f6e70

7.3 OSD 创建后必做的配置

# ① 检查 CRUSH 层级是否正确（默认会把所有 OSD 放在同一个 root 下，没有 host 分层！）
ceph osd tree
# 如果看到所有 osd 都挂在 root default 下而没有 host 层，需要手动加 bucket：

ceph osd crush add-bucket ceph-osd1 host
ceph osd crush add-bucket ceph-osd2 host
ceph osd crush add-bucket ceph-osd3 host
ceph osd crush add-bucket ceph-osd4 host

ceph osd crush move ceph-osd1 root=default
ceph osd crush move ceph-osd2 root=default
ceph osd crush move ceph-osd3 root=default
ceph osd crush move ceph-osd4 root=default

ceph osd crush move osd.0 host=ceph-osd1
ceph osd crush move osd.1 host=ceph-osd1
# ... 逐个移动（或用下面的循环）
# for i in 0 1 2 3 4 5; do ceph osd crush move osd.$i host=ceph-osd1; done

# ② 按容量设置 weight（8TB 盘 → 8.0）
ceph osd crush reweight osd.0 8.0
# 或者让 ceph-volume 自动设（默认按设备大小设，通常是对的）：
ceph osd df tree   # 检查 WEIGHT 列

# ③ 确认故障域是 host（关键！）
ceph osd crush rule dump replicated_rule | grep -A2 chooseleaf
"op": "chooseleaf_firstn", "num": 0, "type": "host"

# ④ 设置 device class（混用 SSD/HDD 时自动分类，一般会自动识别）
ceph osd crush class ls
ceph osd crush set-device-class ssd osd.0    # 手动指定

# ⑤ 验证
ceph -s
ceph osd df tree
最容易踩的坑：忘记把 OSD 移动到 host bucket 下。
如果所有 OSD 都在 root 下平铺，CRUSH 的故障域 host 就无法正常工作 —— 3 副本可能全部落在同一台机器上，那台机器一挂数据就没了。
务必用 ceph osd tree 确认层级是 root → host → osd 三层结构。

只有需要文件存储时才需要这一章。如果只用 RBD/RGW，可以跳过。

# ① 创建数据目录

# ② 创建 keyring

  mon 'profile mds' mgr 'profile mds' osd 'allow rwx' mds 'allow' \
  -o /var/lib/ceph/mds/ceph-ceph-mon1/keyring
chown -R ceph:ceph /var/lib/ceph/mds

# ③ 启动（ceph-mon2/3 同样操作，形成 1 active + 2 standby）
systemctl enable --now ceph-mds@ceph-mon1

# ===== 创建 CephFS =====
# 方式 A：一条命令搞定（推荐，会自动建池 + 配置 MDS）
ceph fs volume create cephfs
# 等价的手动方式：
# ceph osd pool create cephfs_metadata 64 64
# ceph osd pool create cephfs_data     256 256
# ceph fs new cephfs cephfs_metadata cephfs_data

# ④ 验证
ceph fs status cephfs
ceph fs ls
ceph mds stat
cephfs:1 {0=ceph-mon1=up:active} 2 up:standby

# ⑤ 元数据池放到 SSD（强烈建议）
ceph osd pool set cephfs_metadata crush_rule ssd_rule   # 需先创建 ssd_rule

# ===== 客户端挂载 =====
# 内核挂载（性能好）
mkdir -p /mnt/cephfs
mount -t ceph ceph-mon1:6789,ceph-mon2:6789,ceph-mon3:6789:/ /mnt/cephfs \
  -o name=admin,secret=AQD...,ms_mode=crc,noatime,_netdev

# 或用 secretfile（更安全）
cat /etc/ceph/ceph.client.admin.keyring | grep key | awk '{print $3}' > /etc/ceph/admin.secret
chmod 600 /etc/ceph/admin.secret
mount -t ceph ceph-mon1,ceph-mon2,ceph-mon3:/ /mnt/cephfs -o name=admin,secretfile=/etc/ceph/admin.secret

# 写入 /etc/fstab 实现开机挂载
echo "ceph-mon1:6789,ceph-mon2:6789,ceph-mon3:6789:/ /mnt/cephfs ceph name=admin,secretfile=/etc/ceph/admin.secret,noatime,_netdev 0 2" >> /etc/fstab

# ceph-fuse 挂载（用户态，功能更全）
ceph-fuse -n client.admin -m ceph-mon1:6789 /mnt/cephfs
MDS 高可用配置：默认 1 active + N standby，主 MDS 挂了 standby 需要几十秒接管。要求秒级切换时，配置 standby-replay：

mds_standby_for_name = ceph-mon1
# 重启 mds.ceph-mon2 生效

11.2 换盘（OSD 故障更换）

# ===== 场景：osd.5 所在的磁盘损坏，需要更换 =====

# ① 先设置 noout，避免不必要的数据抖动（可选但推荐）
ceph osd set noout

# ② 停止 OSD 并移出集群
systemctl stop ceph-osd@5
ceph osd out 5
ceph osd purge 5 --yes-i-really-mean-it   # 一次性删除 OSD + CRUSH + auth（推荐）
# 等价的分步操作：
# ceph osd crush remove osd.5
# ceph auth del osd.5
# ceph osd rm 5

# ③ 物理更换硬盘后，确认新盘设备名
lsblk
# ⚠ 务必确认，别选错盘

# ④ 清理新盘残留
wipefs -a /dev/sdX
sgdisk --zap-all /dev/sdX

# ⑤ 重新创建 OSD（会复用原有的 OSD ID 或分配新 ID）
ceph-volume lvm create --data /dev/sdX --block.db ceph-nvme0/db-osd-5

# ⑥ 移到正确的 host bucket
ceph osd crush move osd.NN host=ceph-osd1

# ⑦ 取消 noout，观察恢复
ceph osd unset noout
ceph -w

11.3 缩容：下线 OSD 节点

# ① 逐个把该节点上的 OSD 标记为 out（不是直接停！让数据先迁走）
ceph osd out osd.18
ceph osd out osd.19
# ... 逐个 out，每 out 一个等数据迁移完再下一个

# ② 等待集群恢复 active+clean
watch ceph -s

# ③ 停止服务并清除
ssh root@ceph-osd4 "systemctl stop ceph-osd.target"
for i in 18 19 20 21 22 23; do
    ceph osd purge $i --yes-i-really-mean-it
done

# ④ 移除 CRUSH 中的 host
ceph osd crush remove ceph-osd4
ceph osd tree   # 确认已消失

# ⑤ （可选）清理 LVM
ssh root@ceph-osd4 "vgremove -f ceph-* && pvremove /dev/sdb /dev/sdc ..."
缩容铁律：① 必须 逐个 out，等前一个迁移完再下一个；② 确认剩余容量足够容纳迁出的数据；③ 迁移期间限速；④ 绝不能同时 out 超过 m 个（副本池 m = size-1，EC 池 m = 校验块数），否则会丢数据。

14.2 group_vars/osds.yml —— OSD 磁盘定义（三种写法）

# /root/ceph-ansible/group_vars/osds.yml
# ----- 写法 A：全部使用 collocated（数据与 db 同盘，适合全闪/测试）-----
cat > group_vars/osds.yml <<'EOF'
osd_objectstore: bluestore
devices:
  - /dev/sdb
  - /dev/sdc
  - /dev/sdd
  - /dev/sde
  - /dev/sdf
  - /dev/sdg
EOF

# ----- 写法 B：data + 独立 db（HDD 集群推荐）-----
cat > group_vars/osds.yml <<'EOF'
osd_objectstore: bluestore
devices:
  - /dev/sdb
  - /dev/sdc
  - /dev/sdd
  - /dev/sde
  - /dev/sdf
  - /dev/sdg
# dedicated_devices 与 devices 一一对齐：第 1 块数据盘用第 1 块 db 设备
dedicated_devices:
  - /dev/nvme0n1     # 给 /dev/sdb  用
  - /dev/nvme0n1     # 给 /dev/sdc  用
  - /dev/nvme0n1     # 给 /dev/sdd  用
  - /dev/nvme1n1     # 给 /dev/sde  用
  - /dev/nvme1n1     # 给 /dev/sdf  用
  - /dev/nvme1n1     # 给 /dev/sdg  用
# ansible 会自动在 NVMe 上按需创建 LV（每个 db 默认大小 = 数据的 4% 或可指定）
EOF

# ----- 写法 C：lvm_volumes（最精细，可指定 db/wal 大小、device class）-----
cat > group_vars/osds.yml <<'EOF'
osd_objectstore: bluestore
lvm_volumes:
  - data: /dev/sdb
    db: /dev/nvme0n1
    db_size: "60G"
    wal: /dev/nvme0n1
    wal_size: "4G"
    crush_device_class: hdd
  - data: /dev/sdc
    db: /dev/nvme0n1
    db_size: "60G"
    crush_device_class: hdd
  - data: /dev/sdd
    db: /dev/nvme0n1
    db_size: "60G"
    crush_device_class: hdd
  - data: /dev/sde
    db: /dev/nvme1n1
    db_size: "60G"
    crush_device_class: hdd
  - data: /dev/sdf
    db: /dev/nvme1n1
    db_size: "60G"
    crush_device_class: hdd
  - data: /dev/sdg
    db: /dev/nvme1n1
    db_size: "60G"
    crush_device_class: hdd
EOF
关于 db_size：每块 8TB HDD 的 block.db 建议 40~80GB。太小的后果是 RocksDB 溢出到慢设备，性能断崖式下降（见原理篇 9.3）。
关于 NVMe 承载数量：一块 NVMe 上不要放超过 6~8 个 OSD 的 db，否则 NVMe 会成为新的瓶颈，而且它一坏会连带所有 OSD 一起挂。

A附录：cephadm 快速方案（官方主推）

如果你不需要完全掌控部署细节，cephadm 是目前官方推荐的部署方式，基于容器（podman/docker）。下面是极简流程，供对比参考。

# ① 所有节点：安装依赖 + 配置容器运行时
dnf install -y podman lvm2 chrony
# Ubuntu: apt install -y docker.io lvm2 chrony

# ② 在第一个节点安装 cephadm
curl --silent --remote-name --location https://download.ceph.com/rpm-squid/el9/noarch/cephadm
chmod +x cephadm
./cephadm add-repo --release squid
./cephadm install
cephadm --version

# ③ 引导集群（只执行一次）
cephadm bootstrap --mon-ip 10.10.10.11 \
  --cluster-network 192.168.100.0/24 \
  --allow-fqdn-hostname \
  --initial-dashboard-user admin \
  --initial-dashboard-password YourStrongPassword \
  --dashboard-password-noupdate
# 完成后会输出 Dashboard 地址 https://ceph-mon1:8443/

# ④ 复制 SSH 公钥到其他节点
ssh-copy-id -f -i /etc/ceph/ceph.pub root@ceph-mon2
ssh-copy-id -f -i /etc/ceph/ceph.pub root@ceph-mon3
ssh-copy-id -f -i /etc/ceph/ceph.pub root@ceph-osd1
# ... 依次对所有节点

# ⑤ 把主机加入集群
ceph orch host add ceph-mon2 10.10.10.12
ceph orch host add ceph-mon3 10.10.10.13
ceph orch host add ceph-osd1 10.10.10.21
ceph orch host add ceph-osd2 10.10.10.22
# 或批量：ceph orch host add ceph-osd{3,4} 10.10.10.2{3,4}

# 打标签（用于指定守护进程部署位置）
ceph orch host label add ceph-mon1 mon
ceph orch host label add ceph-mon2 mon
ceph orch host label add ceph-mon3 mon

# ⑥ 部署 MON / MGR（cephadm 会自动扩展到 5 个，可用下面命令指定）
ceph orch apply mon ceph-mon1,ceph-mon2,ceph-mon3
ceph orch apply mgr ceph-mon1,ceph-mon2
# 或用标签：ceph orch apply mon --placement="label:mon"

# ⑦ 部署 OSD
ceph orch device ls                        # 查看可用磁盘
ceph orch apply osd --all-available-devices   # 使用所有空闲盘
# 指定盘：
ceph orch daemon add osd ceph-osd1:/dev/sdb
# 指定 db 设备：
ceph orch daemon add osd ceph-osd1:data_devices=/dev/sdb,db_devices=/dev/nvme0n1

# ⑧ 部署其他服务
ceph orch apply mds cephfs --placement="3 ceph-mon1 ceph-mon2 ceph-mon3"
ceph fs volume create cephfs
ceph orch apply rgw myrgw --placement="2 ceph-mon1 ceph-mon2" --port=7480

# ⑨ 常用运维
ceph orch ps                    # 查看所有守护进程
ceph orch ls                    # 查看服务
ceph orch host ls
ceph orch device ls
ceph orch daemon restart osd.0
ceph orch daemon add osd ceph-osd1:/dev/sdh   # 扩容
ceph orch osd rm 0              # 下线 OSD
ceph cephadm shell              # 进入 ceph 命令行容器

# ⑩ 升级
ceph orch upgrade start --ceph-version 19.2.4
ceph orch upgrade status
对比项cephadmceph-ansible / 手动
部署复杂度低（几条命令）中~高
可掌控度中（容器内部不透明）高（每个进程、配置文件都可见）
排障难度需要懂容器/podman直接看进程和日志
升级一条命令，最方便需手动滚动升级
离线环境麻烦（需要镜像仓库）简单（本地 rpm 源即可）
与现有 Ansible 体系集成一般天然契合
学习价值低（屏蔽了细节）高（能真正理解 Ceph）
选型建议：
· 新集群、团队熟悉容器、追求升级便利 → cephadm
· 已有 Ansible 体系、等保/内网离线环境、需要完全掌控 → ceph-ansible
· 学习 / 排障 / 小规模特殊环境 → 手动部署（本文第二部分）
